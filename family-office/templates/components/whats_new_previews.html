Passphrase-Protected Backups, Safer Saves & Your State From Sign-In
v0.5.5 • Security & Data Integrity

.fovault backups now require a passphrase you choose per export, saves no longer read older encrypted values as zero, and a new household starts in its sign-in state or asks before continuing.

Passphrase-Protected .fovault (Format v2)
Export needs a 12-128 character passphrase, the key is wrapped with scrypt and AES-256-GCM, and restore refuses a wrong passphrase or an old unprotected file
Saves Keep Older Encrypted Values
Saves use the same key ring as reads, so Copy previous year no longer stores blank amounts, and an undecryptable value raises an error
State From Sign-In, or Ask
A supported sign-in location sets the starting state; otherwise it shows "State not set" and onboarding asks, with no borrowed state tax rules
Demo Personas Match the Engine
Demo households were retuned and their plan text and Monte Carlo figures recomputed from the current tax, Social Security, ISO/AMT and ACA engines
